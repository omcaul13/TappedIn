# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

TappedIn: up to four live games in one window that switch to a better game during commercial breaks (college football first; NFL, men's/women's college basketball, NBA, WNBA, NHL, MLB, soccer, ATP/WTA tennis). One castLabs Electron window shows 1–4 channels from the user's TV service (Xfinity On Campus is the tested one; others are experimental provider adapters), each screen on its own sport, and a director switches each screen's channel based on ESPN live data (long break → best other live game by 3 tiers: same sport, another screen's sport, any sport; halftime/intermission → highlights reel; final → game picker). README.md is the detailed user-facing doc (modes, switching rules, measured results); read it before changing switching behavior.

## Commands

- `npm test`: vitest (`test/**/*.test.ts`, 120 s timeout because the replay tests are slow)
- One file: `npx vitest run test/director.test.ts`. One test: `npx vitest run test/director.test.ts -t "name substring"`
- `npm run typecheck`: `tsc --noEmit` over `src`, `scripts`, `test`. There is no build step or linter. Everything runs through `tsx`, and the UI is bundled at runtime by esbuild.
- `npm start -- --dry-run`: real ESPN data, data tiles instead of video (uses no streams)
- `npm start -- --replay 20261017 --from 19:30 --speed 10`: a recorded day, sped up, on data tiles (add `--synth` for a day built by `fetch-day`)
- `npm run sim -- --day 20261017 [--from HH:MM --to HH:MM] [--compare] [--sensitivity low|medium|high] [--model classic]`: runs the real engine headless over a recorded day and prints switching metrics. Use this to evaluate any change to the detector, ranker or director.
- `npm run sim -- --day <date> --synth --by-sport [--screen-sports nhl,cfb,cfb,cfb] [--full-lineup] [--no-regional]`: per-sport switching report (`--full-lineup` treats every game as watchable)
- `npm run fetch-day -- <date> --sports nhl,nba|all` / `npm run record -- --sports …`: other sports' data (records carry `sport`; none = CFB)
- `npm run build-break-model [-- --sport <id>]`: rebuilds `config/break-models/<sport>.json` from every recording (CFB's shipped model only when `--sport cfb` is given)

Plain `npm start` launches live Xfinity streams, and `npm run sign-electron` uploads the Electron binary to castLabs. Ask before running either one.

## Architecture

Data flow: **ESPN source → `Engine` (pure, deterministic) → commands → `WindowController` → Xfinity views**, coordinated by `src/app.ts`.

- **Sports (`src/sports/`):** each sport is a `SportModule` (`types.ts`): ESPN league path, parsing (phases, situation, play-by-play), scoreboard inference, break rules (`breaks`: categories, resumes, ignore, model file), Low/Medium/High presets, excitement (0–100 score + hot moment + same-sport `compare`), synth, highlights. Families share code (`football.ts`, `basketball.ts` + `leagues.ts`, `hockey.ts`, `baseball.ts`); `index.ts` is the registry. College football is today's code moved unchanged: `test/cfb-golden.test.ts` compares its full decision sequences with ones frozen before the refactor (`UPDATE_GOLDEN=1` only if a CFB change is intended).
- **The engine is pure and clock-injected.** `src/engine/engine.ts` (`Engine.tick`) takes snapshots and a `now` you pass in. Live mode, replay/sim (`src/sim.ts`) and tests all run the same code, so keep wall-clock time, I/O and randomness out of `src/engine/`.
  - `gameStore` holds per-game state, accounting for the ~25 s ESPN delay and ~30 s video delay.
  - Break detection produces an `Assessment` (`LIVE`/`BREAK`/…) per game. The default is `forecastDetector` + `forecast`, which use the empirical stoppage model in `config/break-model.json`. `breakDetector` is the older "classic" weighted-signal model, kept for `--model classic` comparisons.
  - `ranker` scores substitute candidates in 3 tiers (same sport by the sport's `compare`; then another screen's sport, then any sport, by normalized excitement). `director` is a pure per-screen state machine: `directorStep` for automatic switching (respects dwell and locks) and `applyAction` for user commands (bypass dwell). Every `Decision` carries a `rule` (e.g. `BREAK_FILL`, `FILL_REPLACE`, `HOME_SYNC`) and non-empty `reasons`.
  - `invariants.ts` defines rules the director must never break: no duplicate games unless flagged, dwell respected, lineup-only channels, fill-ins only during a home-game break, best tier first. `test/replay.test.ts` checks them over real recorded data in `test/fixtures/replay-20261017/`. It asserts the invariants rather than exact switches, so threshold tuning shouldn't break it, but an invariant violation is a real bug.
- **Data sources are interchangeable** (`src/espn/source.ts`): `LiveSource` (two-tier polling: fast play-by-play for on-screen games and likely substitutes), recorded-day replay (`recordings/<date>/` ndjson), or a day synthesized from final play-by-play (`espn/synth.ts`, made by `fetch-day`). `espn/normalize.ts` turns raw ESPN JSON into `GameSnapshot`/`PlaySnap`.
- **Shells:** `electron` (default) is `electron/main.cjs`, a CommonJS Electron main that only does layout (1–4 screen views per `electron/layout.cjs` + standby views + a transparent UI view) and the service's sign-in. Request/reply IPC (`ReplyRouter` in `src/shell.ts`): `configure` rebuilds the views in place for another service, screen count or standby count (view titles get a `-g<n>` generation suffix), `logout` clears that service's partition, `signin-check`, `reveal`, `paths`. It reads everything about the service from the `--provider=<file>` that `src/shell.ts` writes (`shellProvider`); its pure page rules are in `electron/signin-rules.cjs`. `src/shell.ts` spawns it, talks over Node IPC, and attaches to its views over the debugging port with `playwright-core`, so `src/windows/` drives them the same way it drives the fallback `chrome` shell (`src/windows/chrome.ts`, `npm run start:chrome`). Electron args must be `--name=value`, never space-separated.
- **Providers (`src/providers/`):** each TV service is a `ProviderAdapter` (`types.ts`) built from `config/providers/<id>.json`, which holds every fragile site detail: URLs, selectors, timings, error text, sign-in rules, hide CSS, and the `tuning` section the adapter's family validates. A user's fixes go in `.state/providers/<id>.json`, which is deep-merged one section at a time. A section that doesn't validate is dropped with a warning (`registry.ts`).
  - Families: `comcast` (`comcast/tvapp.ts` + `adapter.ts`: Xfinity On Campus, Xfinity Stream, Cox; in-app guide binary search → cached URL → full guide load) and `url` (`url/adapter.ts`: one page load of a per-channel URL, or for services without one (Hulu, DIRECTV) `tuning.click`: open the guide, click the channel's row and the play tile; lineup ids read from guide DOM, from the guide JSON the page downloads, or a fixed list (ESPN)).
  - `lineup.ts`: a scanned lineup in `.state/lineups/<id>.json` replaces `channels` from the config file. `networks.ts` matches guide names to ESPN network names. The engine still sees channels as numbers and knows nothing about providers.
  - Adapters may only navigate to URLs and click the service's own guide or buttons. Never call private page functions, rewrite requests, or hook app state; reading the DOM or the page's own responses is fine. Only Xfinity On Campus auto-clicks anything (its Watch Now hand-off).
  - `npm run provider-check -- <id> [--scan [--save]] [--tune ESPN,FS1] [--views N]` exercises one adapter without the engine (live streams: ask first).
- **`src/windows/`:** `controller` applies only the latest wanted state per screen and handles standby views, retries, drift back to the right channel, and stream limits. `tuner` is the service-independent part of a channel change: at most `timing.maxParallelTunes` at once, full page loads one at a time with `timing.loadGapMs` after each (simultaneous Xfinity loads land on each other's channel), and a per-provider URL cache (`.state/xfinity-urls.json` for Xfinity On Campus, `.state/urls-<id>.json` otherwise). `health` polls each screen every 2 s using the provider's error rules. `inject/*.js` are page scripts injected into the video views.
- **UI:** Preact in `src/ui/`, bundled on demand by `src/ui/build.ts` (rebuilds on change, Ctrl+R in the window). `src/server/` is a localhost-only server for the UI, in-screen pages (data tile, halftime reel, picker), server-sent-event state, and a JSON API. POSTs require the `x-tappedin: 1` header and a same-origin request.
- **First-run setup (`src/setup/`):** `.state/setup.json` (`state.ts`) says whether setup is done for `cfg.provider`; an existing Xfinity On Campus install is migrated to done. Until then the app runs in setup mode: shell started with `--signin=defer`, no ESPN polling or engine ticks. `SetupRunner` (`runner.ts`) does choose → sign in → scan → play test → stream test → finish behind injected `SetupDeps`, and `--setup-demo` runs it with fakes (no window) for UI work. The settings page's service actions and diagnostics (`diagnostics.ts`, `export.ts`) go through the same app routes (`/api/setup/*`, `/api/service/*`, `/api/diag/*`). Exports must stay free of cookies, page text and URL queries/fragments.
- **Installer (repo root + `scripts/`):** `Setup TappedIn.cmd` / `scripts/setup.ps1`, `Update TappedIn.cmd`, `TappedIn.cmd`, `npm run doctor`. The end-user installer is `installer/tappedin.iss` (Inno Setup, per-user), built by `scripts/build-installer.ps1` (stages `git archive HEAD`, `npm ci`, the Widevine signature, a pinned `runtime/node.exe`) and by `.github/workflows/release.yml` on `v*` tags; `TappedIn.cmd` uses `runtime\node.exe` when present. Shortcuts run `electron.exe electron\launcher.cjs` instead, which starts the same thing with no console window (output in `logs/launcher.log`, a message box if it exits with an error). Never run their install or signing steps without asking; `-CheckOnly` is read-only.
- **Config:** `config/tappedin.config.json5` is the one user-editable file. Every key has a default and a zod schema in `src/config.ts` (`parseConfig`), and most sections hot-reload via `Engine.setConfig`. Settings changed in the app go to `.state/settings.json` and override the config file. When you add a knob, add it to the schema/defaults in `src/config.ts` and document it in the json5 file. `test/helpers.ts` `testConfig()` builds a config with a small fixed lineup. Use it and the `snap`/`play`/`view` builders in tests.
- **Channels:** `channels.ts` maps ESPN network names (`aliases`) to the guide channel `number` and Xfinity `callSign`. `number: null` means the network isn't in the lineup.

## Conventions and constraints

- ESM TypeScript (`"type": "module"`, bundler resolution, extensionless imports). `electron/*.cjs` stays CommonJS.
- Logs: switch decisions and timings go to `logs/decisions-*.jsonl`, which `analyze-log`/`switch-stats` read. `recordings/`, `logs/`, `.state/`, `.chrome-profile/` and `spike-report/` are gitignored local data.
- The app must never extract or redistribute streams, touch DRM, type credentials, or click Xfinity's Terms of Activation. Sign-in is only the user's own "Watch Now" click. Keep it that way.
